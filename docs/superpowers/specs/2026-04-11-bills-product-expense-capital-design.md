# Bills and Product Expense Tracking Design

## Problem and Goal
The project needs expense tracking that supports:

1. A dedicated Bills form with status handling.
2. Product expense tracking automatically based on Stock-In capital values.
3. Financial totals that reflect approved business rules.
4. Menu behavior that keeps one Financial Analytics entry and uses tabs inside the expenses page.

## Approved Scope
In scope:
1. Bills CRUD (`paid/unpaid`) with bill-specific fields.
2. Auto-created Product Expense records for each new Stock-In action using incoming capital.
3. Separate tabs/lists for Bills and Product Expenses under `/financial/expenses`.
4. Financial totals include **paid bills only** plus **all product expenses**.
5. Keep Financial Analytics as a single Owner-only menu entry (no extra menu links).

Out of scope:
1. Historical backfill of existing Stock-In capital rows.
2. Employee access to these new expense features.
3. Edit/delete for Product Expense rows.

## Chosen Approach
**Approach A (approved): Dual-table + tabbed UI**

Why this approach:
1. Clear data ownership: manual bills and automatic product expenses are separated.
2. Easy to enforce read-only behavior for product-cost records.
3. Keeps menu simple and consistent with user preference.

## Architecture
The existing `FinancialAnalyticsController` remains the entry point. The expense module is split into two internal tracks:

1. **Bills track (manual):** handled entirely inside Financial Analytics pages with full CRUD and status updates.
2. **Product Expense track (automatic):** generated by `StockInController` after successful Stock-In save, using request-level capital input.

UI architecture:
1. One route: `/financial/expenses`.
2. Two tabs: **Bills** and **Product Expenses**.
3. Financial dashboard summaries aggregate both sources using approved rules.

## Components
### Database
1. **`bills` table**
   - `id` (PK)
   - `bill_name`
   - `amount`
   - `bill_date`
   - `due_date`
   - `status` (`paid` or `unpaid`)
   - `notes`
   - `recorded_by` (FK users.id)
   - `created_at`, `updated_at`

2. **`product_expenses` table**
   - `id` (PK)
   - `stock_in_id` (FK stock_in.id)
   - `amount`
   - `expense_date`
   - `source_label` (e.g., `"stock-in-capital"`)
   - `created_at`

### Backend
1. `FinancialAnalyticsController`
   - Bills CRUD actions.
   - Expenses page loader with tab-aware datasets.
   - Totals aggregation methods that combine:
     - paid bills
     - product expenses
2. `StockInController`
   - On successful stock-in transaction, insert one `product_expenses` row from incoming capital.
3. New models
   - `Bill`
   - `ProductExpense`

### Frontend
1. Update `app/Views/financial/expenses.php`:
   - tabbed interface (`Bills`, `Product Expenses`)
   - Bills form and Bills table with status/actions
   - Product Expense read-only table
2. `app/Views/Reusables/menu.php`:
   - keep single `Financial Analytics` nav item only (no additional menu entries).

## Data Flow
### Bills flow
1. Owner submits bill form.
2. Validate bill fields and amount/date rules.
3. Save to `bills`.
4. Bills table supports update/delete and status changes.
5. Totals include only rows where `status = paid`.

### Product Expense flow
1. Owner/employee performs Stock-In.
2. Stock-In save succeeds with incoming capital value.
3. System writes one `product_expenses` record:
   - `stock_in_id` from saved/merged stock-in row
   - `amount` from incoming capital for that request
   - `expense_date` from stock-in date
4. Product Expense list is read-only in UI.

### Totals flow
For each financial window (daily/weekly/monthly):
1. Revenue = receipts totals (existing rule).
2. Expense = paid bills + product expenses.
3. Net Income = Revenue - Expense.
4. Profit Margin = `(Net Income / Revenue) * 100` with zero-safe handling.

## Error Handling
1. Bills validation errors return explicit field messages.
2. If Product Expense insert fails during Stock-In, rollback Stock-In transaction.
3. Product Expense mutating routes are not exposed.
4. Non-owner access to Bills/Product Expense pages is blocked.
5. Aggregation methods default safely to `0` for empty datasets.

## Testing Strategy
1. Bills CRUD tests (create/edit/delete/status + validation).
2. Stock-In integration test confirms Product Expense auto-insert behavior.
3. Read-only test ensures Product Expense has no edit/delete path.
4. Financial totals test verifies:
   - unpaid bills excluded
   - paid bills included
   - product expenses included
5. Navigation test confirms menu remains one Financial Analytics entry and tabs appear on expenses page.

## Implementation Notes
1. Apply this as an incremental change to the current Financial Analytics module.
2. Replace existing manual `Expense`/`ExpenseCategory` usage with `bills` for manual expenses, and stop using old manual expense tables in financial totals to avoid duplicate sources.
3. Use existing flash/redirect UI conventions already used by stock and financial pages.
